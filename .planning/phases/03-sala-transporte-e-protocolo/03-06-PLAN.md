<objective>
Dar memória e credencial ao servidor: a tabela append-only que grava o desfecho de cada
conexão ICE, e a credencial efêmera de TURN emitida por HMAC dentro do próprio signaling.

Purpose: a taxa de necessidade de relay deste grupo de amigos é hoje um número de terceiros
(10-20% por par, 27-49% numa sala de quatro). D3-14 existe para substituí-lo por medição — e
**a linha de falha também é gravada**, porque sem ela a tabela mede só os sucessos e a taxa
fica errada para cima. A credencial de TURN é o que permite ao relay existir sem um endpoint
aberto convidando o mundo a usar a nossa banda.

Output: `002_ice_outcome` aplicada, `turnCredential` com vetor conhecido, e um servidor que sobe
sem segredo de TURN avisando em vez de morrer.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| peer → servidor (`iceOutcome`) | O corpo do reporte vem de uma máquina remota; a sala e o peer são resolvidos pelo socket, nunca pelo que o cliente diz |
| servidor → coturn | Compartilham o `static-auth-secret`, que nunca atravessa a fronteira servidor → cliente |
| servidor → SQLite | Segunda tabela do banco; append-only, sem dado pessoal além do ULID local |
| `/etc/dg2/env` → processo | O segredo é lido do arquivo de env, nunca de código versionado (D2-15) |
